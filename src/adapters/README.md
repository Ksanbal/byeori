# Host adapters

`hooksConfig(host)` supplies the generated plugin's exact `hooks/hooks.json`. B10 bundles `hook-entry.ts` as adjacent `runtime/hook.mjs`; `runtime/cli.mjs` and the existing worker/Studio remain the shared CLI runtime. Hook commands use documented hook-time `CLAUDE_PLUGIN_ROOT` or `PLUGIN_ROOT`, quoted for spaces. They do not assume those variables exist in ordinary Bash. Consumers need supported Node24; project dependencies/build are unnecessary. Missing/runtime-failed PreToolUse returns exit2 through the shell launcher, while SessionStart failures inject a resume pointer and return0. The hook's own stdin/work watchdog is 8 seconds; configured host timeout 15 seconds leaves time to emit the blocking result.

CLI init preflights both managed instruction files, initializes Core planning/ignore, then installs AGENTS.md guidance and CLAUDE.md's @AGENTS.md link. Managed instruction markers include only their own span; all original bytes outside remain unchanged, including CRLF and missing final newline. Existing `.claude`/`.codex` config, permissions, hook entries, `.gitignore` outside the Core block, `.plan`, planning/source/review/workflow and source files are preserved. Init does not install/trust a plugin or claim configured hooks. Plugin registration remains the host's documented plugin installation; no project hook config needs to be edited or duplicated. Malformed/duplicate instruction markers, unsafe paths and writer/CAS conflicts fail without overwriting unrelated files. IO failure can leave a partial instruction install: rerun idempotently after inspection; never roll back over a later user edit.

`host remove` removes only managed instruction spans and resets/removes adapter observations. Existing planning and the Core ignore block remain. Uninstall/disable the Byeori plugin through the native host to remove its generated hook entries; removing local guidance does not uninstall an active native plugin. Other plugins/settings are not changed. Existing explicit human advisory selection remains durable.

| Input path | Supported bounded behavior |
| --- | --- |
| Claude `Write`/`Edit` | Documented absolute file_path plus required string content/edit fields; checked through Core |
| Codex canonical `apply_patch` | command envelope, Add/Update/Delete and Move-to paths; every origin/destination checked; malformed instructions deny |
| `Read`, `Grep`, `Glob` typed inputs | Read paths through Core; no inference from arbitrary tool names |
| `Bash` / documented exec_command alias | literal `pwd`, `cat -- <paths>`, `touch -- <paths>`, `mkdir -- <paths>`, `rm -- <paths>` only; installed same-release `node <absolute-cli> ...` delegates its own strict Core-bound commands |
| Operators, substitutions, scripts, redirections, globs, unknown/MCP tools | Unknown coverage, deny through Core; no generic shell parser or silent advisory fallback |
| Existing `write_stdin` session | No new native PreToolUse documented; continuation coverage cannot be claimed |
| Hosted/specialized tools or cloud orchestration | Native hook execution is not guaranteed/supported; outside local protection claims |

Relative patch/shell paths resolve from the actual event cwd; nearest initialized project ancestor supplies binding. Canonical root aliases are mapped without normalizing away caller `.`/`..` segments. Core rejects symlink descendants, Unicode/case collisions, planning/source/reviews/host records, stale source/apply/authorization and any path outside the frozen human allowlist. Draft writes are allowed only in the current mutable change. No explicit `allow` permissionDecision is emitted: success leaves normal host permissions in place. Denial uses hookSpecificOutput PreToolUse permissionDecision deny at exit0. Malformed/oversized UTF-8 stdin/runtime timeout is exit2. PreToolUse errors fail closed in initialized projects; outside any initialized project the adapter has no product policy and emits no decision.

SessionStart startup/resume/compact emits bounded additionalContext with project/workspace binding and actual source/apply/change/review/authorization state, plus AGENTS/workflow and readback pointers. It does not block compaction, replace its summary, read/store transcripts, include whole documents/workflow text, or store raw conversations/secrets. State errors produce an inspection pointer, never a guessed approval.

Native proof is deliberately narrow. Only the installed dedicated runtime may observe the immediate native host parent, or one command-shell parent whose full command exactly matches the generated hook handler and then the immediate native host. Arbitrary ancestor searches are forbidden because ordinary tools/tests also descend from Codex. The native executable's version and PID/start/boot identity, current generated definition/runtime hashes and project/workspace binding must match; known trust-bypass/disable flags reject promotion. The adapter records time and nonsecret evidence under planning/hosts and a disposable planning/.runtime/adapters probe. It never writes native trust hashes. Trust is inferred from exact native execution under the documented review flow, not stdin fields or binaries on PATH. Unsupported process chains/versions remain configured=false, trusted=null, active=false, probe blocked. Linux automated Core/fixture tests do not establish Linux native support.

`refreshHosts(root)` is the CLI/Studio observation surface. Ordinary callers cannot prove current in-memory host enablement, so active=false means current activation is **unverified**, not that the user disabled it. Valid last observation trust can remain for 5 minutes; expired/cache-missing, changed/removed definition/runtime or ended/replaced native process clears configured/trusted and reports blocked. Ordinary `gate check` refreshes before Core, so a persisted active claim cannot grant stale enforcement. Enforced native preflight requires a fresh literal --hook-ticket and one-use receipt as described below. The currently executing exact native hook observes/promotes immediately before its Core gate; the exact native CLI preflight may consume that current observation once through its bound receipt. Concurrent doctor/UI refresh can conservatively demote between observation and gate; this fails closed and is retryable, never grants permission. Human advisory is preserved independently and still requires fresh applied authorization/exact scope; unknown operations continue to deny.

This is local process/definition evidence, not protection from a privileged process or malicious same-OS account, forged executable/config/runtime or deliberately reproduced native call. Native B13 trust/activation/disable/restart tests remain required. Stdin child fixtures and simulated cache records are labeled synthetic and cannot count as native proof. The strict exact-chain probe may reject legitimate host wrappers until their actual chain is verified; no permissive fallback is used. The installed hook entry resolves legitimate filesystem aliases; the separate pre-existing CLI symlink-entry limitation remains B10's scope.

Official formats rechecked 2026-10-08: [Codex hooks](https://learn.chatgpt.com/docs/hooks) and [Claude Code hooks](https://code.claude.com/docs/en/hooks). Both document command JSON stdin, PreToolUse deny output and SessionStart additionalContext. Codex documents non-managed hash-bound trust and plugin hooks alongside local hooks; Claude documents hook-only plugin environment variables. Documentation and synthetic replay do not verify native installation.


Enforced CLI preflight uses a two-step literal workflow: the separate read-only `node -e "console.log(require('node:crypto').randomUUID())"` returns a fresh UUID, which is pasted into `node "<actual-cli.mjs>" gate check --root "<actual-project-root>" --json --hook-ticket "<fresh-UUID>" --input '<JSON GateRequest>'`. The hook recognizes only this unambiguous literal token order, verifies same installed CLI identity and the exact six-field GateRequest, runs Core's gate, re-observes the current dedicated native hook chain and issues a receipt. There are no shell substitutions, wrapper commands, generic command execution from parsed text or reusable example tickets. Explicit workdir/cwd overrides on shell inputs remain unknown coverage.

Receipt data contains request/argv/command/session hashes, installed CLI/hook/definition hashes, native process/start/boot identity, project binding and issuance time, with no raw command/request/session/credentials. CLI consumption is one-use and lock-fenced even on mismatch. It rechecks the current identical disposable probe, same immediate native process and exact literal invocation, installed identity/hashes and a two-second age before repeating Core. Missing/expired/consumed/mismatched, disabled/changed definition, missing cache, ended native process or concurrent active demotion fails closed. Same native process plus one-use invocation correlation is the guarantee; session_id hash is additional event provenance, not independently established same-session identity. Receipt preflight is not future authorization: each actual protected-write hook repeats the gate and native observation. Slow startup or unsupported process wrappers may exceed the bounded window; rerun with a new UUID after inspection, never extend acceptance or silently select advisory. Synthetic bundle/CLI startup measured in the test run does not prove native timing.
