# Re-enter from durable state

Resolve the same installed CLI and explicit project/worktree as in commands.md. Re-read the real cwd/repository and project instructions, then run status. Compare project_id/workspace_fingerprint; a changed root/worktree is not interchangeable. Do not use a conversation summary, cached approved flag, .delivery, development model settings or a different release's runtime as authority.

Read workflow.version, focus, facts, assumptions, open_questions, correction_attempts and next_action; active_change; current_round and manifest_hash; pending_submissions and processed_comment_ids; source_integrity, apply_state and implementation_authorization. Preserve existing interview answers and unsent user input with workflow write using the current workflow version, keeping unrelated fields. Store only necessary nonsecret context, not raw whole conversations. For an input that cannot safely fit the bounded workflow/argv profile, retain it privately with the user's normal workspace tools and say which part is not durable; do not silently truncate or write approval/source records.

For an active change, history --change returns a type:change entry with its current version. Obtain mutation CAS there rather than reconstructing a hash or using a remembered version. For a prepared round, derive ReviewBinding from the actual status binding, active change ID, current_round and manifest_hash, then read review results. Do not re-submit or create another change just because the previous response was lost.

Before feedback response, preserve a stable response ID and exact JSON request in a labeled workflow fact, together with the real submission/comment IDs. Re-read results after a process/session boundary: if that response is already present, acknowledge readback; if absent and comments remain unprocessed, resend the same response ID and payload. A changed payload needs a new ID and current CAS after reconciling what succeeded. Never resend a comment already handled by another response. Update workflow.feedback_progress with the observed response_id using workflow CAS, not a conversation inference.

If apply may have succeeded, inspect status/applied/history first. An already applied target is not a new approval; do not create another apply or new change to repeat its effects. If apply_state/source_integrity indicates recovery, use recover action inspect with the actual binding/change ID; resume only after its conflicts are understood and resolved through the normal Core recovery path. Unknown ownership is not permission to delete a lock, overwrite source, reset Git or restore a guessed snapshot.

Review completion speech only triggers durable readback. No accepted submission means remain waiting and end the turn. Mixed/pending/blocking feedback means respond/revise, not apply. Fresh complete approval permits frozen apply; implementation authorization still requires the actual gate and frozen paths. Never treat approved documentation as implementation completed. Terminating a session does not arrange an automatic restart; when waiting, state the resume cue without promising background polling.

Automatic planning correction is bounded to two ordinary attempts plus one cause-analysis/escalation attempt per change. Persist observed counts in workflow.correction_attempts as { change_id, ordinary, escalation } with workflow CAS. Stop the automatic loop when this budget is exhausted or a new user decision is needed; do not reset counts to keep trying. Host reasoning/semantic review remains separate from deterministic lint, and no development-team model policy is written into the user project.
