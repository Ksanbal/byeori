# 벼리 빠른 시작

벼리는 Claude Code와 Codex의 터미널 대화에서 기획·질문·리뷰 내용을 다룹니다. 최종 승인은 보호된 터미널에서 진행합니다. 기획 문서는 별도 읽기 전용 브라우저 뷰어로 볼 수 있습니다.

1. 호스트 플러그인을 설치하고 Node 24.13 이상 24.x를 선택한 뒤 `init`, `doctor`로 프로젝트와 실제 훅 상태를 확인합니다.
2. start/change 스킬로 인터뷰합니다. 네이티브 질문 도구가 없으면 채팅으로 답합니다. 확정 사실·가정·미응답은 구분해 저장하며, 인터뷰 답변은 구현 승인이 아닙니다.
3. 보조자가 초안과 삭제·범위·검증 계획을 설명하고 lint 후 `review prepare`로 고정합니다.
4. **사용자가 직접 Terminal/iTerm 등 지원되는 터미널 셸에서** 실행합니다. 보조자에게 이 명령의 입력을 대신 시키지 마세요.

```sh
node <플러그인경로>/runtime/review.mjs --root <프로젝트경로>
```

고정 문서의 변경 전후와 경로를 읽고 항목마다 `approve`, `request_changes`, `pending` 또는 명시적 `keep`을 입력합니다. 최종 단계에서 `planning-only` 또는 `allow-implementation`을 직접 선택합니다. 구현을 원할 때만 후자를 고르세요. 마지막 요약과 manifest를 확인한 뒤 표시된 `SUBMIT …` 문구를 정확히 입력합니다. 기본 선택·체크박스·파이프 승인 입력은 없습니다.

제출 후 보조자에게 알려 실제 결과를 읽게 하세요. 기획 apply와 범위 안 코드 작업은 별도입니다. 새 경로는 새 리뷰가 필요합니다. Ctrl-C 또는 quit로 멈추면 최종 제출 없이 이미 저장한 판단만 남으며, 같은 리뷰를 다시 실행해 이어갈 수 있습니다. 다른 회차나 내용으로 바뀌면 재검토해야 합니다.

명령이 AUTH_REQUIRED로 거부되면 권한·훅을 낮추지 말고 [지원 터미널과 제약](terminal-review.md)을 확인하세요. 기존 기획·승인 이력은 보존되며 과거 false 구현 허용이 자동으로 true가 되지 않습니다.


## 읽기 전용 문서 뷰어

```sh
node <플러그인경로>/runtime/viewer.mjs --root <프로젝트경로> --port 4317
```

출력된 로컬 주소를 브라우저에서 열면 Kumo 기반 문서 목록·본문·2D 관계도를 볼 수 있습니다. 상단 문서 소스에서 현재 source 또는 변경 세트를 고르면 새로 생성된 초안도 확인할 수 있습니다. 미완성 초안은 검증 알림과 YAML 원문으로 표시됩니다. 9종 문서 탭, IA 계층 트리, 아키텍처 연결, 스크롤·드래그·확대 탐색을 지원합니다. 기록된 상태는 승인 증명이 아니며, 뷰어에는 편집·승인·제출 기능이 없습니다. 종료는 Ctrl-C입니다. 개발 저장소에서는 `pnpm viewer --root <프로젝트경로> --port 4317`로 실행합니다. Notion 이전·동기화는 구현되지 않은 후속 과제입니다. [사용법과 경계](document-viewer.md)를 참고하세요.
