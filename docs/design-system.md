# Studio design system

Studio uses React/TypeScript, Vite, Tailwind4 and the installed official shadcn/ui new-york Radix registry. Exactly two global destinations, 문서/리뷰, share the small document list and content body. At narrow widths the list moves into a labelled modal Sheet. History/details open only on request; Sheet title/description and normal Radix focus restoration remain intact. Korean text uses the platform sans-serif stack; no copied fonts or external font requests. Animation respects reduced-motion preference.

Button, Sheet, Tabs, Input/Field, Badge, Table, Separator, Alert, Empty and Collapsible are official CLI registry files. Their upstream compositions/variants and Radix semantics remain. The five design rules besides no-restyle still apply inside UI implementations. No policy suppression or visualization directory exemption exists. Registry arbitrary ring3px, padding3px, checkbox translation2px, negative offset5px and transition values are expressed through Tailwind scales/standard utilities. The Tabs full-height utility replaces upstream minus1px height. Alert's optional icon column is declared as named `alert-grid`/`alert-icon-grid` CSS utilities to preserve its two-column structure without arbitrary class values. Card colors alias background/foreground; Sheet overlay uses foreground opacity. `tw-animate-css` provides actual upstream Sheet animations. No inline geometry exception is used.

Native document kinds have explicit field-specific sections, tables and lists including IDs, schema, aliases, relations and blocking questions. OpenAPI has operation metadata plus a complete recursive definition-list view of every original standard/extension value, including booleans/null/empty collections. Strings, Markdown and remote references remain escaped text, never active HTML or fetched refs. Raw YAML is supplemental and collapsed by default.

Only scenario/IA/screen/entity/architecture data diagrams have deterministic sketch-like polygon offsets. DataDiagram uses the source document and fixed640-unit canvas size as seed; SVG coordinates are attributes, colors are semantic utilities/currentColor, and labels use ordinary sans text. Native IDs/relationships drive nodes and edges. No shell, control or font is sketched. Zoom changes only display size and can reset. SVG title/description provide complete labels; the complete field tables below supply a text fallback. Small screens scroll the drawing rather than shrink its text to unreadability.

The HTTP client establishes the authenticated session, retains CSRF only in memory and sends bounded read POSTs through exact document/history routes. Abort/key ownership prevents old selected documents replacing newer views. Current approved, current drafts and exact frozen before/after revisions are separately labelled. Draft navigation uses only actual approved IDs or the last prepared manifest's entries: it explicitly does not claim a complete index of unprepared drafts. Loading/error/retry and no-record states reflect real server responses. History separates change/review/submission/response/applied/implementation/cancelled records, pages25 at a time and opens exact frozen revisions. Full hashes/runtime data and backend diagnostic detail live in the details Sheet; source drift/recovery/stale warnings and implementation scope stay visible.

Dialog, Textarea, Select and Checkbox were added through the pinned official CLI for B07. Dialog positioning uses Tailwind fractions and normal screen bounds; rings, radii and transitions use standard utilities. Select's upstream Radix available-height, origin and trigger-size variables are retained as named CSS utilities. Long comment pointers wrap and Select triggers remain within their field width. No lint rule was relaxed.

Review decisions start pending. Classified comments use stable document/element/operation/field/pointer targets. One per-tab HTTP queue and a bound review session serialize actual feedback versions; a saved indicator means the server acknowledged that body. Conflict/stale/network errors preserve typed input and offer explicit retry or a copied local snapshot before reload. A new manifest opens only through explicit reset. The single final Dialog presents all decisions, blockers, purpose, reason, deletions, permission changes and exact implementation scope. Planning-only is the default; implementation permission requires an explicit checkbox and the frozen scope hash. Unknown submission outcomes remain locked until actual durable results are read; retries retain the original submission ID and body. Final decisions are read-only.

Semantic diffs and complete before/after bodies come from exact frozen revisions. Historical navigation uses that round's actual deltas, including deleted IDs. Approval, source application and implementation evidence have separate history records; missing reasons are labelled 미기록. Host status shows recorded observations with a current-activation warning and requires an explicit reason/acknowledgment for human advisory mode. It does not present persisted evidence as current enforcement. Completion asks the user to tell their agent 리뷰 완료; it does not wake agents.

Validation is executable: tests/studio/documents.test.tsx checks every native/OpenAPI source value without raw YAML, escaping and deterministic diagram data; tests/studio/browser.test.ts checks real separate Chrome against the real Core-backed HTTP server, nine views, remote-ref safety, history/focus restoration, mobile navigation and zoom at1440x900/1024x768/390x844. tests/studio/review-browser.test.ts exercises genuine synthetic four-item approval/save/submit/apply and gate outcomes, two-tab conflicts, changed drafts/new rounds, delayed typing, invalid/network saves, submission response loss and identical-ID retry, fresh sessions and classified targets. Keyboard, focus restoration, reduced motion and content width are checked in normal isolated headless Chrome at all three viewports. The synthetic baseline is explicitly submitted through authenticated HTTP; no production bootstrap helper is added. Manual user-profile Chrome remains blocked by ERR_BLOCKED_BY_CLIENT; no security setting/profile was modified. Tooling effective-config and positive/negative tests remain unchanged.
