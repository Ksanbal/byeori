# Native host verification

## Independent release gates

Record machine/OS, supported Node, exact installed host version, authentication availability, loaded plugin/runtime/definition hashes, canonical project binding and original file hashes. Installation alone is not actual hook activation. Preserve current trust/permission settings; no skip-permissions, automatic trust choice or advisory fallback.

For **each** Claude Code and Codex independently, verify:

1. Actual startup/resume/compact context and exact native hook identity.
2. Native interview/question delivery, a real human answer and durable CAS persistence; pause with unresolved input and resume without inventing an answer.
3. Official web research (including supported pagination) and project/skill reads, separate from host permission decisions.
4. Real model-driven draft/lint/freeze, then human-visible terminal review of the exact manifest and paths. The person operates the separate reviewer directly; the agent never supplies its judgment input.
5. Actual unapproved write denial and unchanged fixture hash.
6. A real human final terminal submission: exact per-item decisions and explicit scope-bound permission; durable readback before apply.
7. Actual native apply/preflight and successful in-scope file tool write. A preflight receipt alone is not later tool execution.
8. A harmless out-of-scope sentinel attempt denied with unchanged hash.
9. Interrupted/restarted native session retaining the correct facts, pending questions, frozen review, applied authorization and scope without duplicate approval or implicit widening.

Use separate synthetic projects and nonsecret data. Classify every stage as passed, failed, blocked or not run, identifying host trust/permission, hook activation, input schema, instructions, stale runtime or human transport boundaries. The human terminal's own direct-input test is also required; agent-owned PTYs must be denied.
