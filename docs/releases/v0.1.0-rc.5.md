# v0.1.0-rc.5 — read-only Kumo document viewer prerelease

This release adds an optional, local, read-only planning document viewer built with pinned Cloudflare Kumo components, React and locally bundled styles/icons. It does not restore web review, approval or editing.

## Document navigation

- Nine persistent document-kind tabs make generated PRD, actors, scenarios, feature specifications, IA, screens, entities, API and architecture documents discoverable, including empty kinds.
- Choose current source or a specific saved change set. Drafts retain their own provenance and are not merged into source or presented as approved.
- Search documents, inspect readable structured sections or raw YAML, follow relationships, and navigate using keyboard controls and browser history.
- IA parent/subitem hierarchy is visible in a nested outline and a pannable, zoomable two-dimensional tree. Architecture displays explicit source connections. Truncation and invalid/incomplete records carry visible warnings.

## Boundaries

Run `node <plugin>/runtime/viewer.mjs --root <project> --port 4317` with Node >=24.13.0 <25, then open its printed loopback URL. The viewer is opt-in, serves only allowlisted local assets and known planning records, and has no editing, feedback, submission, apply, approval or permission-change endpoint. No consumer build, dependency install, CDN or external service is required. Other local processes that can reach the port may read planning content; stop it when finished and never publish or reverse-proxy the port.

The protected terminal reviewer remains the only supported final human review transport. Source visibility and recorded lifecycle labels are not independent proof of approval. Existing immutable receipts, hooks, gates and exact implementation-scope rules are preserved. Notion import/export/synchronization and migration remain backlog work.

## Verification and limits

The release VERIFICATION.md records the exact source commit, final automated checks, CI runs and asset hashes. Automated coverage includes React/Kumo DOM interactions, source/draft separation, hierarchy, navigation, stale requests, server methods/origins/paths, read-only/no-write behavior, deterministic payload generation, relocated consumers and archive integrity.

Real-browser visual and interaction acceptance has **not** been completed. The cloud browser could not connect to the separate executor loopback server (ERR_CONNECTION_REFUSED); the executor browser attempt was blocked by a socket EPERM restriction. No screenshot-based or real-browser visual pass is claimed.

Positive directly operated human-terminal acceptance/final submission and the complete current Claude Code/Codex native flow remain **independently unverified**, as in rc.4. Automated service/DOM/hook fixtures do not establish native activation, human approval or current-session hook trust. The terminal/process ancestry guard is bounded local transport checking, not cryptographic proof of a human or a defense against malicious same-user OS/filesystem control.

## Updating

Preserve existing planning records and follow the supported marketplace/plugin update flow in [Installation](../installation.md). Fixed release tags do not advance automatically; the guarded `release` branch tracks verified published releases, including prereleases. Close the owning host session before updating and start a fresh one afterward. Read durable status/review/workflow before continuing. Downloading or publishing this release does not install a plugin, accept hook trust, change permissions or grant implementation authorization.
