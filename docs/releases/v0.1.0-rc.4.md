# v0.1.0-rc.4 — terminal review prerelease

The local review website and HTTP server have been removed. The assistant interviews, drafts plans and discusses frozen changes in Claude Code/Codex. A person records the final judgment by running the separate `runtime/review.mjs` directly in a supported terminal.

The reviewer requires explicit item decisions, a separate planning-only or exact-scope implementation choice, and a manifest-bound final confirmation. It saves drafts with CAS, supports pause/resume, and rejects pipes, approval flags, agent process ancestry and unknown terminal wrappers. The agent CLI has no approval or advisory command. Legacy web receipts remain readable without changing their judgments or promoting implementation permission.

Web UI components, browser tooling, server/worker entrypoints, web-only dependencies and packaged assets are removed. The two host bundles still contain identical offline CLI/reviewer/hook runtimes and require Node >=24.13.0 <25. No consumer dependency installation or build is required.

The related Claude compatibility fixes are retained: validated WebFetch character offsets, documented native question shapes and bounded discovery/skill/project-document reads defer to the host's own permissions. Unknown fields, executable shell forms, unsupported reads and protected writes keep their existing gates. Host permission refusal is never treated as an instruction to bypass a gate.

## Verification limits

Automated checks exercise Core approval/scope/apply/recovery, real isolated child processes, relocated consumers, terminal denial paths, synthetic human feedback and packaging integrity. Exact candidate commands, counts, CI and checksums are recorded in the release's VERIFICATION.md asset.

Positive directly operated human-terminal acceptance and final submission have **not** been completed. The complete new flow in an actual loaded Claude Code session and in Codex is **not verified independently**: interview answers, research, review, approved in-scope native writes, out-of-scope denial and interrupted-session resume remain native release gates. Earlier Claude Code 2.1.296 partial native observations do not validate the new flow or the currently installed 2.1.303 host. Fixture approval and hook replay do not prove native activation.

TTY/process ancestry is a bounded local transport check, not cryptographic physical-human proof or a defense against malicious same-user OS/filesystem control. Unsupported terminals and wrappers fail closed. An earlier isolated hook exit2 was not root-caused; detailed failure diagnostics were added and later isolated/full runs passed without relaxing timeouts or deny conditions.

## Updating

Preserve planning records and use the host's supported marketplace/plugin update commands. Downloading this prerelease does not grant hook trust or change host permissions. Start a fresh host session and read durable status/review/workflow before continuing. New terminal receipts may be refused by older runtimes; never rewrite provenance or discard later human decisions to force a downgrade.

On the MacBook Air, the pre-publication registration check found neither Byeori nor its marketplace in the default Claude Code or Codex installation. Isolated test loading is separate. Installing it there would be a new installation and may require human hook-trust review; it is not claimed as an existing-plugin update.
